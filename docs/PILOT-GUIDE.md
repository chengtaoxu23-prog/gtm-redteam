# GTM-RedTeam Pilot Guide

围绕一个可反驳的商业问题完成双轮研究。公开资料案例不是客户验证。

1. 准备问题、目标市场、客户群和有权处理的资料。客户保密材料须取得对本地保存、外发 DeepSeek 和研究用途的明确知情同意；没有授权就使用公开材料。
2. 按 README 启动。默认数据位于本机 `data/audits`，包括 workspace JSON、原件与决策账本；可用 `GTM_DATA_DIR` 指定隔离目录。勾选授权并启动研究后，所选资料发给配置的外部模型。JSON 和导出可能含原文，不能随意公开；备份整个数据目录。
3. 新建项目，填写问题、市场和客户。在 Evidence Ledger 上传资料或登记 URL。检查页码、Sheet/Cell、公式缓存、Hash、警告和未知发布日期。解析失败的来源不能引用。
4. 生成 Contract 草案，人工填写成功／失败条件、窗口、指标、方法和门槛，确认完整性后锁定。尚不明确的标准可以保持不完整，但不能伪装成验证完成。
5. Run 1：勾选外发授权并研究。逐条核对引用原文，分别检查引用存在、语义支持和对假设的实际影响。记录研究起止时间及自己的人工核验起止时间。
6. 查看总片段、已评估、未读、覆盖比例和待研究 Chunk。选中不等于已评估，已评估不等于结论成立，已读未发现不等于全文没有反证。
7. Run 2：加入新竞品、定价、访谈或监管材料，或用 Delta 补读长文档。确认新增证据关联正确假设；无关和重复内容不应制造审批。失败时恢复原 Run，不通过重复新建绕过额度。
8. 人工接受／拒绝／进一步研究并填写理由。修改标准时创建新版本；旧报告仍解释旧契约。
9. Reports 导出 Markdown 和完整 JSON。复核 Historical Research Context、Current Hypothesis State、覆盖与 usage；账本保留研究与决策历史。

试点记录包含问题、授权范围、材料清单、Run IDs、实际研究时间、人工核验时间、引用错误、漏读内容和决定理由。未测量填“未测量”。本轮没有真实客户验证或人工核验效率数据。

停止条件：没有外发授权、来源不可追溯、解析失败、共享额度用尽或证据不足。保留记录并解决具体问题，允许停在待研究，不补造结论。
